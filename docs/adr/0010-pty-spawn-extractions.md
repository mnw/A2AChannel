# `pty_spawn` extracts `build_spawn_argv` + `ensure_session_configured`; silent failures replaced with `Result` propagation

`src-tauri/src/pty.rs`'s `pty_spawn` was a 64-line orchestrator interleaving six concerns (agent-name validation, room resolution, registry idempotency, MCP-config materialization, locale resolution, session-existing-vs-new branching, tmux argv assembly, attach). The session-existing branch at line 369 called `configure_existing_session(&agent, &lang);` whose body was ten `let _ = tmux_run(...)` calls — every tmux failure swallowed silently, including the CLAUDE.md-load-bearing `remain-on-exit off`. Argv assembly bugs (the v0.6 regression class where quoted paths-with-spaces got split by `/bin/sh`'s argv-join) lived inline rather than at a named seam with its own test. The post-2a code audit (finding #5) flagged this as a god function with silent-failure paths and a missing orchestrator-level integration test that CLAUDE.md's per-helper rule was specifically designed to prevent.

This decision implements `architecture-cycle-2b` §5 (partial — orchestrator-level integration test deferred) and was committed in `bfe8e87` ahead of the rest of cycle 2b's gated implementation.

## Considered Options

- **Single `spawn_orchestration(...)` extraction:** rejected — would just rename the god function. The named-seam payoff comes from extracting the two atomic operations (argv build + ensure-configured) so each gets its own focused test.
- **Keep `let _ = tmux_run(...)` for backward compatibility:** rejected — silent failure is exactly the bug class CLAUDE.md's `pty.rs` hard rule was written to prevent.
- **Rewrite `pty_spawn` from scratch with a builder pattern:** rejected — over-scope. The shape is correct; only the inline-orchestration noise needs to leave.
- **Extract three or more helpers (e.g., separate `resolve_room_for_spawn`, `materialize_mcp_config`, `make_lang_envs`):** rejected — those are pure-call wrappers around existing single-line operations. Pulling them out adds named-function noise without concentrating any complexity.

## Consequences

- **`build_spawn_argv(agent, cwd, lang, api_key, spawn_cmd) -> Vec<String>` is a pure function.** No I/O, no tmux invocation, no environment reads. Returns the tmux `new-session -d -s <agent> -e ... -x 80 -y 24 -c <cwd> <spawn_cmd>` argv as owned strings. Critical quoting invariant: `spawn_cmd` passes as a SINGLE argv element so `/bin/sh`'s argv-join doesn't split quoted `--mcp-config '/path with spaces.json'` into multiple tokens (the v0.6 regression).
- **`ensure_session_configured(agent, lang) -> Result<bool, String>`** replaces `configure_existing_session`. Returns `Ok(true)` when an existing session was reconfigured (forced `remain-on-exit off`, window-size resize+latest, env-var injection), `Ok(false)` when no session exists (caller creates via `new-session`), `Err` when a critical tmux operation fails. Critical operations (errors propagate): `set-option remain-on-exit off`, `resize-window -A`, `set-option window-size latest`. Best-effort operations (errors logged, not propagated): status bar toggle, `TERM`/`COLORTERM` env-var injection, LANG/LC_ALL re-application on existing sessions, `allow-passthrough`, `refresh-client`.
- **`pty_spawn` body collapses to ~12 LOC** of clear sequencing: validate name → resolve room → registry idempotency → `spawn_cmd + api_key + lang` → `ensure_session_configured(...)?` → `build_spawn_argv` if new → `tmux_run(&argv)?` → `attach_and_stream`. Errors from the critical tmux operations now propagate to the Tauri command result instead of being swallowed.
- **7 new pure-function unit tests** in `src-tauri/src/pty.rs spawn_argv_tests` (`cargo test --lib spawn_argv` passes in ~10ms, no tmux required): argv starts with new-session form, includes terminal env vars, includes ANTHROPIC_API_KEY when provided, omits it when None, includes `-x 80 -y 24 -c <cwd>`, passes `spawn_cmd` as single element (v0.6 quoting regression guard), preserves cwd-with-spaces as single element.
- **`pty_spawn_shell`** (the second caller of the old `configure_existing_session`) migrated to `ensure_session_configured` too. Returns `Ok(true)` for the existing-session branch; the additional `allow-passthrough` + `A2ACHANNEL_SHELL` env-var setup runs only on the existing-session path (preserved behavior).

## Post-implementation lessons

- **The `let _ = tmux_run(...)` pattern was silently masking a CLAUDE.md hard-rule failure.** The `remain-on-exit off` operation is what prevents claude's natural exit from leaving a dead pane that blocks tab-close. If tmux returned a non-zero exit for any reason (socket missing, permission, racing with a parallel command), the session would silently stay misconfigured. The migration to `Result` propagation exposed exactly which operations are load-bearing vs cosmetic — and the cosmetic ones (status bar, env-var injection on long-running sessions) are explicitly tagged as best-effort with logged warnings.
- **Best-effort fallbacks need explicit `eprintln!`s, not silent `let _ =`.** The audit's framing pushed for full `Result` propagation across all ten tmux calls. Implementation revealed half of them are genuinely best-effort (re-setting LANG on an already-running session is mostly cosmetic; `refresh-client` is a redraw). Documenting WHICH calls are best-effort with logged failures is the right shape — better than either uniform `?` propagation (which would fail spawn on cosmetic issues) or uniform silent suppression (which masked the load-bearing failures).
- **Pure-function unit tests pay off immediately.** The 7 `spawn_argv_tests` ran sub-10ms in `cargo test --lib`. Compared to the integration-test cost of spinning up tmux to verify argv shape, the pure-function tests give 100x faster feedback for the exact bug class (v0.6 quoting) that we want to lock down with regression coverage.
- **Orchestrator-level integration test deferred.** The audit specifically called for one new scenario in `tests/integration/pty-plumbing.test.ts` asserting `pty_spawn` end-to-end (session created with `remain-on-exit off`, `LANG` env set, raw-PTY mode preserved). The scenario needs the Tauri-IPC layer or a test-double; deferred from this commit because the test infrastructure isn't trivially in place. The per-helper test coverage (existing `pty-plumbing.test.ts` scenarios + new `spawn_argv_tests`) carries forward — the gap CLAUDE.md's per-helper rule was designed to prevent is partially closed; the full closure ships when the orchestrator-level test lands.

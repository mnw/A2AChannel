## Why

`architecture-cycle-2a` (Hub-only) lands first and soaks for a week before this cycle starts. Three layers of friction remain that 2a deliberately deferred:

1. **The Webview has no Kind abstraction.** `ui/kinds/handoff.js` (classic `<script>`), `ui/kinds/interrupt.js`, `ui/kinds/permission.js` each reimplement card creation/update/teardown with `(id, version)` reconciliation by hand. They share `ui/main.js`'s lexical scope (12+ globals: `messagesEl`, `authedFetch`, `parseErrorBody`, `askReason`, `escHtml`, `HUMAN_NAME`, `addMessage`, `trimMessages`, `updateCountdownLabel`, `handoffCards`, `interruptCards`, `permissionCards`) — no module boundary, no exports.
2. **Per-Kind CSS is spread across 5 sources.** `ui/kinds/handoff.css` (112 LOC), `ui/kinds/interrupt.css` (86 LOC), `ui/kinds/permission.css` (183 LOC) hold mostly Kind-specific rules — 381 LOC total. `ui/styles/card.css` (67 LOC) holds the shared `.handoff-card / .interrupt-card / .permission-card` skeleton (border, radius, padding, grid). `ui/features/rooms.js` lines 125-127 inject runtime CSS that references the same per-Kind class names for the room-filter feature. `ui/styles/chat.css` is already clean of Kind-specific rules. Adding a 4th Kind today means duplicating ~150 LOC of card-lifecycle JS + a new `<kind>.css` + remembering to add the class to `card.css` + remembering to add it to `rooms.js`'s injected rule.
3. **`src-tauri/src/pty.rs`'s `pty_capture_turn` uses closure-defer for cleanup** of the geometry/pipe-pane/sentinel triplet. Three try-blocks + manual cleanup arms; fragile to early returns and panics. RAII via `Drop` is the idiomatic Rust shape.

This cycle carves the Webview `KindRenderer` + `KindCard` lifecycle, migrates `ui/main.js` and `ui/kinds/*.js` to ES modules with explicit imports/exports (the `<script>` shared-lexical-scope trick is incompatible with `KindRenderer` factories), consolidates per-Kind CSS from `ui/kinds/<kind>.css` + `ui/styles/card.css` + `ui/features/rooms.js` into `ui/styles/kinds.css` keyed by `data-kind`, splits `ui/terminal.js` (873 LOC) into `Tab` + `XtermBinder` + `PtyEvents`, and rewrites `pty_capture_turn` around a `CaptureTransaction` with `Drop` cleanup.

## What Changes

- **Carve `KindRenderer` interface + `KindCard` lifecycle owner in the Webview.** Each Kind module exports a `KindRenderer` with `extractSnapshot(entry): Snapshot`, `mount(snapshot, container, dispatch): void`, `dispatch(verb, payload): Promise<void>`, and `placement: "stack" | "pin" | "append"`. (Pre-grill 0.2 re-evaluates whether to split `mount` into `buildHeader` / `buildBody` / `buildActions` — current strawman is a single `mount` plus an optional `decorate(container, snapshot)` hook for shared chrome; the 4-builder shape is only earned if `KindCard` injects shared chrome BETWEEN sections, which today it doesn't.) `KindCard` owns the per-card lifecycle (create on first version, update by `(id, version)` with newer-wins, dismiss on terminal status — the dismiss policy is per-placement; see design.md Decision 1's dismiss matrix).
- **Migrate `ui/main.js` + `ui/kinds/*.js` to ES modules with a `ctx` factory pattern.** Today's classic-`<script>` shared-lexical-scope arrangement is incompatible with the `KindRenderer` factory shape. The cleanest migration mirrors the Hub-side `cap` idiom: `createXRenderer(ctx)` where `ctx` carries the helpers each renderer needs (`{ messagesEl, authedFetch, parseErrorBody, askReason, escHtml, humanName, addMessage, trimMessages, updateCountdownLabel }`). `main.js` constructs `ctx` once at startup and hands it to each renderer factory.
- **Consolidate per-Kind CSS into `ui/styles/kinds.css`.** Move per-Kind rules from `ui/kinds/handoff.css` + `ui/kinds/interrupt.css` + `ui/kinds/permission.css` (381 LOC total) into `kinds.css`, keyed by `[data-kind="<kind>"]`. Fold `ui/styles/card.css` (the shared `.handoff-card/.interrupt-card/.permission-card` skeleton) into `kinds.css` as a foundational `[data-kind]` rule — it's literally a Kinds-shared schema. Migrate `ui/features/rooms.js`'s runtime-injected room-filter CSS to use `[data-kind][data-room]` selectors instead of hardcoded `.handoff-card[data-room]` strings — that closes the last island of per-Kind class names outside `kinds.css`.
- **Split `ui/terminal.js` (873 LOC) into `Tab` + `XtermBinder` + `PtyEvents` (gated).** Carve into three modules under `ui/terminal/` (which today holds `pty.js` and `xterm-themes.js`). `XtermBinder.mount(container, opts): Promise<void>` resolves only after geometry-heal SIGWINCH propagates to the PTY master. Gate by the smoke-checklist file `tests/smoke/tab-lifecycle.md` (cold-start race + reconnect storm + theme-change refit + kill+respawn) being completable with all observed-rows passing.
- **`CaptureTransaction` with `Drop` cleanup in `src-tauri/src/pty.rs`.** Today's `pty_capture_turn` uses three try-blocks + manual cleanup arms; replace with a `CaptureTransaction` struct holding the geometry/pipe-pane/sentinel state and using `Drop` for cleanup. Tests assert `CaptureState` is restored on success, timeout, and panic paths.

## Capabilities

### New Capabilities

- `kind-rendering`: Webview-side per-Kind `KindRenderer` interface (factory taking `ctx`) with `extractSnapshot` + `mount` + `dispatch` + `placement`. `KindCard` is the lifecycle owner; chat-pane code never calls into per-Kind DOM directly. CSS consolidates from 5 sources into one `kinds.css`. Per-placement dismiss matrix surfaces on the renderer (or via a placement-aware `dismiss` callback — settled in pre-grill).
- `tab-lifecycle`: `Tab` (cold-start / reconnect / dispose), `XtermBinder` (xterm.js write/refit/theme; `mount` returns a Promise that resolves after SIGWINCH propagates), and `PtyEvents` (output / exit / resize) with three clear seams. The cold-start race + reconnect storm + theme refit + kill+respawn invariants from `tests/smoke/tab-lifecycle.md` MUST hold.
- `capture-transaction`: `CaptureTransaction` struct in `pty.rs` owning geometry-set + pipe-pane-on + sentinel-watch state with `Drop` doing cleanup. `pty_capture_turn` becomes a thin wrapper that constructs the transaction and lets `Drop` handle teardown on every exit path.

### Modified Capabilities

- None. 2b is purely additive in terms of capability set; the Hub capabilities from 2a stay unchanged.

## Impact

- **Files affected (Webview JS):** `ui/index.html` (declarative module wiring; per-Kind scripts gain `type="module"`); `ui/main.js` (becomes ES module exporting `createCtx()`; converts the 12+ globals to explicit named exports OR exposes them via `ctx`); `ui/kinds/handoff.js`, `ui/kinds/interrupt.js`, `ui/kinds/permission.js` (each becomes `createXRenderer(ctx): KindRenderer`); new `ui/kinds/kind-card.js` (lifecycle owner); new `ui/kinds/kind-renderer.js` (interface + registry + `KindCard` static dispatcher).
- **Files affected (Webview CSS):** `ui/styles/chat.css` already clean (no per-Kind selectors today); `ui/styles/card.css` folded into `kinds.css`; `ui/kinds/handoff.css`, `ui/kinds/interrupt.css`, `ui/kinds/permission.css` consolidated into `kinds.css` keyed by `[data-kind]`; new `ui/styles/kinds.css` (target ~400 LOC, slightly over 381+67=448 because some duplication consolidates); `ui/features/rooms.js` lines 125-127 migrate to `[data-kind][data-room]` selectors.
- **Files affected (Webview terminal):** `ui/terminal.js` (873 LOC) split into `ui/terminal/tab.js`, `ui/terminal/xterm-binder.js`, `ui/terminal/pty-events.js` (gated by smoke-checklist; the existing `ui/terminal/` directory holds `pty.js` and `xterm-themes.js` today).
- **Files affected (Rust):** `src-tauri/src/pty.rs` (`pty_capture_turn` rewritten around `CaptureTransaction`); new tests under `src-tauri/tests/` asserting cleanup on success/timeout/panic. **Panic-path test requires `std::panic::catch_unwind` + a custom panic hook** (Rust default test runner aborts on panic) — budget half a day for the test alone.
- **Smoke-checklist artifact:** `tests/smoke/tab-lifecycle.md` ships as a tracked file in the repo (the gate for the Tab-split commit). Cycle pre-grill writes it; the Tab-split lands only after all observed-rows pass.
- **New unit-test artifact:** `tests/unit/kind-renderer.test.ts` exercises each renderer's `extractSnapshot` + `dispatch` against a fake `ctx` (no jsdom required — both methods are pure). High-leverage because the renderer is the most-testable surface in the cycle.
- **CLAUDE.md hard rules — multiple anchors to edit:** the "Terminal pane uses a raw PTY" rule's path-references update from `ui/terminal.js` → `ui/terminal/tab.js`/`pty-events.js`. The dev-channels prompt auto-dismiss rule references `terminal.js watches the PTY output stream` — update to point at the new `PtyEvents` module. The Tab cold-start regression-guard rule's path drifts. The `pty.rs` hard rule's commentary updates if `CaptureTransaction` changes the `attach_and_stream` shape. Tasks 5.3 enumerates all four anchors explicitly.
- **No external API breakage.** No HTTP route changes, no SSE event-kind changes, no Tauri command renames. Hub remains untouched.
- **Schema unchanged.** No ledger migration.
- **Migration ordering is sequential, single branch.** Single branch, per-candidate commits, smoke-test gate.
- **Depends on `architecture-cycle-2a` being merged + soaked.** Substantive dependency, not just temporal — 2b's `KindRenderer` mirrors 2a's `LedgerEntity` orchestration shape. If 2a's shape changes during cleanup, 2b's contract may need to follow. Re-grill before 2b starts (see design.md Risks).

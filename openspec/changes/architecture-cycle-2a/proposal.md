## Why

The codebase has accumulated two Hub monoliths — `hub/hub.ts` (901 LOC) and the three near-duplicate `hub/kinds/*.ts` files (~1450 LOC combined) — where structural enforcement of CLAUDE.md hard rules has degraded into convention enforced by code review. Two parallel architecture-skill passes produced complementary plans, merged here for the Hub-side scope: orchestration extraction (`LedgerEntity` hybrid shape — picked via the pre-grill 1.1 INTERFACE-DESIGN.md parallel sub-agent flow on 2026-05-10), `HubFeature` route-module dispatcher, single `Fanout`, and `BriefingDispatcher`. This is **cycle 2a** — the Hub-only cut. Webview + Rust work is tracked separately as `architecture-cycle-2b` and lands on top of a stable, soaked 2a.

## What Changes

- **Carve `LedgerEntity<Snapshot>` out of the three Kind files.** One external Module Kind code learns: `entity.apply(id, verb, payload, cap, scope)` for the common case + `entity.applyWithSideEffect(...)` for cross-table-write cases (today: handoff accept's nutshell patch). An internal `Store<Snapshot>` collaborator (created via `createSqliteStore` for production / `createInMemoryStore` for tests) lives in the entity's closure and is NOT exposed via any property. Each `hub/kinds/<kind>.ts` shrinks to a `StateMachineDecl` + one `VerbDecl` per verb (each verb's `decide` callback returns the `Decision` discriminated-union arm — `idempotent | conflict | transition`). The load → decide → transact → emit skeleton lives once inside `LedgerEntity`. Sub-issue resolved: `events.seq` materializes as a `version` column on the derived row inside the same transaction → `listByStatus` becomes a flat single-query SELECT with no per-row `MAX(seq)` subquery, eliminating today's N+1.
- **Generalize `KindModule` into `HubFeature` (route module).** Carve hub.ts's inline routes (chat, transcript, room settings, attachments, sessions, usage, roster, stream, agent-stream) into modules registered with the dispatcher. Naming TBD via INTERFACE-DESIGN.md grilling — `HubFeature` vs `Surface` vs other; `Module` is rejected because it collides with LANGUAGE.md vocabulary. SSE handlers (Stream, AgentStream) admit a separate sub-shape because their lifecycle is long-lived.
- **Carve `Fanout` module owning all SSE broadcast.** Single `Fanout.send(entry, scope, opts?)` replaces today's three implicit paths (`broadcastUI`, `cap.sse.emit`, ad-hoc loops over `uiSubscribers + agents.values()`). chatLog persistence, transcript write-through, permanent-agent skip, `<private>` redaction-on-persist all live here. `cap.sse.emitWhere` is removed (its sole caller migrates to the new `room-ambient` scope).
- **Carve `BriefingDispatcher` owning re-brief debounce + per-Agent signature dedup.** Lifts `lastBriefingSig`, `briefingFanoutTimer`, `scheduleBriefingFanout` out of hub.ts module scope into `hub/core/briefing-dispatcher.ts`.
- **Delete `cap.ids.mint(prefix, bytes)`** — shallow surface that ignores the prefix and returns `randomId(bytes)`. Kinds already use proper `mintHandoffId` / `mintInterruptId` helpers.

## Capabilities

### New Capabilities

- `ledger-store`: `LedgerEntity<Snapshot>` external Module owning derived-table schema + the atomic event-write+derived-row-update transaction (via internal `Store` closure). Kinds stop seeing raw `db.run` for their tables. `listByStatus` runs in one SQL query (no per-row N+1) because `version = events.seq` is materialized on the derived row.
- `kind-orchestration`: load → decide → transact → emit lifecycle that each Kind specializes via verbs (each carrying a pure `decide(prior, payload, cap)` callback returning a `Decision` discriminated-union arm) + scope + state-machine declaration. Lifecycle and storage are fused inside `LedgerEntity`; idempotency policy lives in each verb's `decide` callback.
- `route-modules`: hub-feature contract (or whatever the grilled name lands at) generalizing `KindModule.routes`. The dispatcher acquires a second adapter type, becoming a real seam; hub.ts's inline routes migrate to dispatcher-resident modules.
- `broadcast-fanout`: single module owning every SSE fan-out path with the `Scope` enum from CONTEXT.md as the contract; chatLog persistence, transcript write-through, `<private>` redaction-on-persist, permanent-agent skip enforced structurally.
- `briefing-debounce`: per-process Briefing re-issue scheduler with debounce-reset-on-call + per-Agent signature dedup, owning its own state instead of leaking it into hub.ts module scope.

### Modified Capabilities

- `kind-runtime`: existing capability whose requirement set is extended. The `KindModule` contract carries a `LedgerEntity<Snapshot>` field (`entity`) replacing today's per-Kind `migrate` and inline transaction code; kinds compose `LedgerEntity` rather than reimplementing the load → decide → transact → emit skeleton inline. The "exactly one event + one derived-table update in one transaction" requirement is enforced structurally via the new `ledger-store` capability rather than per-Kind convention.

## Impact

- **Files affected (Hub TS):** `hub/hub.ts` (~900 → ≤300 LOC wiring); `hub/kinds/{handoff,interrupt,permission}.ts` (handoff 603→~165, interrupt 365→~110, permission 481→~140 per the pre-grill 1.1 estimate); `hub/core/types.ts` (KindModule gains `entity: LedgerEntity<Snapshot>`); `hub/core/ledger.ts` (callers migrate); `hub/core/events.ts` (callers migrate); new `hub/core/ledger-entity.ts` (external) + `hub/core/store.ts` (private internal — created via `createSqliteStore` / `createInMemoryStore` factories); new `hub/core/fanout.ts`, `hub/core/briefing-dispatcher.ts`; route-module extracts under `hub/features/`; `hub/chat.ts` becomes a route-module rather than a half-extracted helper.
- **CLAUDE.md hard rules become structural facts** (not convention): "one event + one derived row in one transaction" (`LedgerEntity.apply` owns the transaction), "same-status retry idempotent / different-status 409" (Decision discriminated-union arms in `decide` callbacks), "never enumerate agent queues from a kind" (Fanout). These rules are deleted from CLAUDE.md as part of section 8.
- **No external API breakage.** All MCP tool names, HTTP route shapes, and SSE event kinds are preserved. The migration is internal.
- **One additive ledger schema migration (v11 → v12).** Adds `version INTEGER NOT NULL DEFAULT 0` to `handoffs`, `interrupts`, and `permissions`; backfills from `MAX(seq) FROM events WHERE entity_id = <table>.id`. This is the structural change that eliminates today's N+1 in `listByStatus` (the post-grill choice to materialize `version` on the derived row rather than compute it via correlated subquery). Forward-only, idempotent. Down-migration is not supported (consistent with prior migrations).
- **Migration ordering is sequential, single branch.** All Hub-side candidates touch hub.ts and the kinds files heavily; parallel branches = merge hell within Hub work. The `architecture-cycle-2a` branch lands its commits, gets a week of soak, then `architecture-cycle-2b` (Webview + Rust) lands on top.
- **Webview + Rust work scoped to `architecture-cycle-2b`.** That cycle covers `KindRenderer` + `KindCard` + kinds.css + `Tab`/`XtermBinder`/`PtyEvents` split + `CaptureTransaction`. It depends on 2a only insofar as 2a's kind orchestration shape (KindBase or fused) is settled — the Webview Kind renderer mirrors the Hub-side abstraction.
